## 一、项目概述

**项目背景**：某高校图书馆需建设“图书情报检索与统计平台”，统一管理馆藏图书、读者信息与借阅流水，并提供多维度检索、分类统计与借阅趋势分析服务。

**业务目标**：基于 MongoDB 完成数据库部署、数据建模、条件检索、聚合统计、索引优化与访问控制，并使用 PyMongo 开发一个菜单式命令行应用，覆盖图书/读者/借阅/统计四大模块。

**组内分工（示例）**：

| 成员 | 负责内容 |
|---|---|
| 成员 A | 任务一环境部署、任务二建库与数据导入 |
| 成员 B | 任务三检索与更新删除、任务四聚合与索引 |
| 成员 C | 任务五 PyMongo 程序开发、任务六 Compass 核对与文档整理 |

## 二、环境与数据建模

### 2.1 部署关键参数

- 数据库进程：`mongod`，监听端口 **27017**，绑定 `127.0.0.1`。
- 自定义数据目录：`./data/db`；日志目录：`./logs/`。
- 访问控制：生产/验收模式以 `--auth` 启动，创建只读账号 `libReader(read)` 与读写账号 `libWriter(readWrite+dbAdmin)`。
- 启动命令（验收模式）：

```bash
mongod --dbpath ./data/db --port 27017 --bind_ip 127.0.0.1 --auth
```

启动成功标志（日志）：`Waiting for connections` 与 `mongod startup complete`。

### 2.2 数据库与集合设计

数据库名 `library`，共 4 个业务集合 + 3 个特殊集合：

| 集合 | 类型 | 关键字段 | 文档数 |
|---|---|---|---|
| `books` | 普通集合 | isbn,title,author,publisher,category,price,stock,rating,tags,publish_date,borrow_count | 20 |
| `readers` | 普通集合 | card_no,name,college,email,phone,level,register_date,fav_categories | 16 |
| `borrow_logs` | **时间序列集合** | borrow_date(time),reader_card(meta),book_isbn,status,return_date | 66（导入）→ 52（D1/D2后） |
| `category_stats` | 普通集合 | 聚合结果（_id=类别） | 5 |
| `book_logs` | **固定集合(capped)** | 容量 1MB、最多 1000 条 | 0 |
| `book_in_stock` | **视图** | 基于 books 过滤 stock>0 | 19 |

\* 时间序列集合设置了 `expireAfterSeconds=157680000`（5 年自动过期）。数据文件导入 66 条流水（时间跨 2023—2025）；在系统当前时间 2026-10 下，5 年保留期可完整覆盖全部借阅记录，TTL 不清理任何数据，导入即 66 条。任务三 D1/D2 删除演示后流水变为 52 条（删 1 条已归还 + 13 条逾期），聚合统计按此 52 条口径呈现（见 3.2）。

三种特殊集合的实现方式：

```js
// 固定集合
db.createCollection("book_logs", {capped:true, size:1048576, max:1000});
// 时间序列集合
db.createCollection("borrow_logs", {
  timeseries:{timeField:"borrow_date", metaField:"reader_card", granularity:"hours"},
  expireAfterSeconds:157680000
});
// 视图
db.createCollection("book_in_stock", {viewOn:"books", pipeline:[{$match:{stock:{$gt:0}}}]});
```

### 2.3 索引设计

| 索引 | 字段 | 类型 |
|---|---|---|
| `uniq_isbn` | isbn | **唯一索引**（重复 ISBN 插入被拒） |
| `idx_title` | title | 单键 |
| `idx_category` | category | 单键 |
| `idx_tags_multikey` | tags | 多键（数组） |
| `idx_cat_price` | category + price | 复合 |

`explain()` 验证：按 `category` 等值查询命中 `idx_category`，执行阶段为 `IXSCAN` 索引扫描，而非全表 `COLLSCAN`。

## 三、功能实现

### 3.1 检索（任务三，实际结果条数）

**基础检索**

| 编号 | 需求 | 操作符 | 结果条数 |
|---|---|---|---|
| Q1 | 定价 > 80 元 | `$gt` | **7** |
| Q2 | 库存 < 10 本 | `$lt` | **8** |
| Q3 | ISBN=9787115428028 精确查 | `$eq` | **1** |
| Q4 | email 为空的读者 | `$eq:null` | **3** |
| Q5 | 排除“人民邮电出版社” | `$ne` | **16** |
| Q6 | 类别∈{计算机,经济管理} | `$in` | **10** |

**组合与高级检索**

| 编号 | 需求 | 操作符 | 结果条数 |
|---|---|---|---|
| Q7 | 评分>4.0 且 计算机类 | `$and` | **7** |
| Q8 | 评分<3.5 或 库存=0 | `$or` | **1** |
| Q9 | 书名含 Python | `$regex` | **1** |
| Q10 | tags 同时含“编程”“入门” | `$all` | **1** |
| Q11 | 恰好 3 个标签 | `$size` | **12** |
| Q12 | 存在 tags 字段 | `$exists` | **17** |

**结果处理**：Q13（`_id` 为字符串，数据预置 1 条 `_id="ISBN-OLD-0001"`）= **1**；Q14 评分降序前 5 为《活着》4.9、《哥德尔证明》4.8、《深入理解计算机系统》4.8、《平凡的世界》4.8、《费马大定理》4.7；Q15 投影仅返回 title/price/rating；Q16 类别清单 = 外语、数学、文学、经济管理、计算机（5 类）。

**更新删除**：U1 指定书库存 -5（`$inc`，modified=1）；U2 经济管理类 9 折（`$mul`，matched=3）；U3 写入时间戳（`$currentDate`）；U4 删除某书 tags（`$unset`）；D1 删 1 条已归还记录；D2 用 `deleteMany` 删全部 13 条逾期记录；D3 `replaceOne` 整体替换读者张明信息（保留 `_id`）。

> 提示：`borrow_logs` 为时间序列集合，D1/D2 的删除操作依赖 MongoDB 7.0 已放开的时间序列删除限制（`deleteMany` 在 7.0 完全可用）。

### 3.4 PyMongo 应用（任务五）

共 6 个源文件：`mongodb_connect.py`（连接封装）、`book_manager.py`、`reader_manager.py`、`borrow_manager.py`、`stat_manager.py`、`main.py`。启动时打印连接状态与三集合文档数；菜单含 9 个功能项（检索/评分排行/分类统计/借阅趋势/畅销榜/读者分布/新增/借阅/归还），每次变更打印受影响文档数，无结果给出提示，退出前关闭连接。实测启动显示：books 20、readers 16、borrow_logs 52（D1/D2 后），各统计项输出正确。

**时间序列集合约束的处理**：`borrow_logs` 为时间序列集合，MongoDB 不支持对其普通字段执行更新，故“归还处理”未使用 `update_many`，而改用 **`deleteMany` 删除在借“借出”记录 + `insert_one` 追加一条“已归还”记录**（两者均为 7.0 时间序列集合允许的操作），同一条借阅始终只保留一条记录，统计口径不变。详见 `borrow_manager.return_book()` 注释。

## 四、问题与核对

### 4.1 调试难点与排查

1. **时间序列集合“数据变少”**：最初 `borrow_logs` 只能查到 26 条，与导入的 66 条不符。排查发现是 `expireAfterSeconds=63072000`（2 年 TTL）后台任务把 2024-10 之前的记录自动过期删除（借阅日期分布在 2023—2025 年，2 年保留期从当前时间倒推）。解决：按要求把保留期改为 5 年（`expireAfterSeconds=157680000`），重建集合后重新导入，66 条流水全部保留。这不是操作错误，而是时间序列集合的生命周期参数设置问题。
2. **启用认证后程序连不上库**：开启 `--auth` 后，所有未带凭据的连接被拒（code 13）。解决：在 `mongodb_connect.py` 中统一使用 `libWriter` 账号并指定 `authSource=admin`，特殊字符 `@` 需 URL 编码为 `%40`。
3. **时间序列集合不支持普通字段更新**：最初“归还处理”用 `update_many` 修改 `status`/`return_date`，被 MongoDB 拒绝（时间序列集合仅允许修改 metaField）。改为 `deleteMany` + `insert_one` 追加“已归还”流水后正常。
4. **唯一索引冲突**：为 `isbn` 建唯一索引时，重复插入测试 ISBN 正确抛出 `DuplicateKeyError`，验证了约束生效。
